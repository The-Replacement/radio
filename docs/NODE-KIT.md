# Run your own circle

This is the **node kit**: a recipe, not a product, for running your own radio
circle. It takes you from a fresh clone to a playing, token-gated stream with
one granted credential. The door stays the door — no credential, **404** — and
what comes through it is yours.

For the **door-only** path (token-gated streaming without a full station
buildout, content generation, camera, or host voice), see
[`docs/DOOR.md`](DOOR.md). This document covers the full circle: the door, the
transport, and the generator that makes the music.

## The circle (ethos, read before you copy)

This radio is a closed circle, not a platform. The constitution is short:

- **The door is the philosophy.** No credential → 404, never 401. The radio does
  not confirm that it exists. Caddy is the only door; Icecast and Liquidsoap
  publish no ports.
- **Own content.** Everything you hear is generated by you (indiegenerator is
  deterministic and offline: seed in, finished tagged track out; no samples, no
  third-party audio). Tracks pass gates before entering.
- **It never restarts itself.** The stream is installed by hand and by gates.
  Silence beats a crash.
- **Privacy-first, DIY, anti-corporate.** No tracking, no analytics, no
  third-party scripts, no algorithms, no ads, no directories. A laptop, a
  `docker compose up`, and a circle of people who hold a token.
- **Ever growing.** The door does not change; what comes through it does.

Running your own circle means running these values, not just this code. The
invitation link is a key you hand to people you trust.

## Prerequisites

- Linux host with Docker Engine and Docker Compose v2 (`docker compose`)
- `git`, `bash`, `curl`, `python3`
- The **indiegenerator** repository available as the build context for the
  `indiegen` service (default: sibling directory `../indiegenerator`; override
  with `INDIEGEN_CONTEXT` in `.env`)
- Disk space and CPU for generation (a render cycle is CPU-heavy; see
  [`docs/INDIEGENERATOR.md`](INDIEGENERATOR.md))

Optional, for the full station beyond a playing audio stream:

- A USB webcam device for the `cam` service (default `CAM_DEVICE` in `.env`)
- Local Kokoro model/voice files for Mario, the host voice (`mario` service;
  see [`docs/MARIO.md`](MARIO.md))
- A host `radio-batch.slice` cgroup slice if you keep `BATCH_CGROUP_PARENT`
  enabled for batch services (see `docker-compose.yml` / infra notes)

## Fresh clone to a playing stream (one granted token)

The path below brings up a **minimal playing circle**: door + stream +
generator. It is the validated end-to-end gate for this recipe. Services that
require hardware or model files you do not have yet (`cam`, `mediamtx`,
`mario`, `tor`) are omitted here; add them once their prerequisites are met
(see [Full station](#full-station-optional-services)).

### 1. Clone radio and indiegenerator as siblings

```bash
git clone https://github.com/The-Replacement/radio.git
git clone https://github.com/The-Replacement/indiegenerator.git
cd radio
```

If indiegenerator lives elsewhere, set `INDIEGEN_CONTEXT` in `.env` (step 2) to
its path. The `indiegen` image is built from that context.

### 2. Configure

```bash
cp .env.example .env

# Replace placeholder Icecast secrets (required before starting the stack)
sed -i "s|^ICECAST_SOURCE_PASSWORD=.*|ICECAST_SOURCE_PASSWORD=$(openssl rand -hex 24)|" .env
sed -i "s|^ICECAST_RELAY_PASSWORD=.*|ICECAST_RELAY_PASSWORD=$(openssl rand -hex 24)|" .env
sed -i "s|^ICECAST_ADMIN_PASSWORD=.*|ICECAST_ADMIN_PASSWORD=$(openssl rand -hex 24)|" .env

# Align runtime ownership with your host user (see .env.example / docs/HARDENING.md)
# Example:
# sed -i "s|^INDIEGEN_UID=.*|INDIEGEN_UID=$(id -u)|" .env
# sed -i "s|^INDIEGEN_GID=.*|INDIEGEN_GID=$(id -g)|" .env
# Repeat for RADIO_UID/GID, CADDY_UID/GID (and MARIO_UID/GID, CAM_UID/GID if used)
```

Prepare runtime directories expected by bind mounts and atomic publish staging
(not all are tracked by git):

```bash
mkdir -p data/caddy data/indiegen data/host data/cam secrets music-audio music \
         music-audio/.tmp music/.tmp
```

Review `.env`: `SITE_ADDRESS`, `FRONTEND_URL`, `PUBLIC_URL`, and `COOKIE_FLAGS`
control the door and invitation links (local defaults work for a local test).
For a public deployment, read [Publishing on the internet](../README.md#if-you-want-to-publish-it-on-the-internet)
in the README and set `COOKIE_FLAGS` to include `Secure` over HTTPS.

### 3. Grant one credential

```bash
chmod +x scripts/*.sh scripts/*.js scripts/*.py 2>/dev/null || true
./scripts/token.sh add you
```

This creates `secrets/tokens.txt` and `caddy/tokens.caddy` (bearer-equivalent,
gitignored, mode 600). To print the invitation link (sensitive):

```bash
./scripts/token.sh reveal you
```

Treat revealed links and token artifacts as secrets.

### 4. Bring up the minimal playing circle

```bash
docker compose up -d --build icecast liquidsoap caddy indiegen
```

(If `liquidsoap` fails to start with a tmpfs mount error on `/music/.tmp`,
ensure `music-audio/.tmp` exists on the host as created in step 2.)

`icecast`, `liquidsoap`, and `caddy` form the door and transport. `indiegen`
generates and rotates the library into `./music-audio` (audio) and `./music`
(metadata). It does **not** run a cycle on start (`--no-run-on-start`) and, by
default, waits for its interval (`INDIEGEN_INTERVAL_SECONDS`, 6 h) or a trigger.

On a fresh clone `./music-audio` has no playable tracks yet, so the stream will
not carry music until the first cycle completes. Trigger one now:

```bash
./scripts/indiegen-cycle.sh
```

This writes `data/indiegen/trigger`, which the running `indiegen` service picks
up. A cycle renders a batch (minutes, CPU-bound) and publishes it atomically.
Liquidsoap watches for new files (additions); deletions from the in-memory
playlist require a Liquidsoap restart in steady-state operation (handled by the
host watcher/signal path in a full deployment — see
[`docs/INDIEGENERATOR.md`](INDIEGENERATOR.md)). For the first cycle populating
an empty library, additions are sufficient; if playback does not start after the
cycle, restart Liquidsoap once:

```bash
docker compose restart liquidsoap
```

### 5. Verify

```bash
./scripts/token.sh check
./scripts/query-gate.sh
```

With the stack running and at least one playable file in `./music-audio`, run
the integration gate:

```bash
./scripts/smoke.sh
```

`scripts/smoke.sh` reads `.env` (`PUBLIC_URL`, `FRONTEND_URL`) and
`secrets/tokens.txt`. The stream-bytes check requires playable audio in
`./music-audio` and a healthy Icecast/Liquidsoap path.

To confirm the door manually (replace `<TOKEN>` with the value from
`secrets/tokens.txt` or `token.sh reveal`):

```bash
# No credential -> 404 (the door does not confirm it exists)
curl -i "http://localhost:8090/stream"

# With credential -> audio
curl -i "http://localhost:8090/stream?t=<TOKEN>"
```

## Full station (optional services)

`docker compose up -d --build` starts every service defined in
`docker-compose.yml`. In a fresh environment some services need extra
prerequisites and will fail to start without them:

| Service | Prerequisite | If missing |
|---|---|---|
| `cam` | Camera device at `CAM_DEVICE` (USB webcam) | Container cannot be created/started; omit or stop it |
| `mediamtx` | Used by camera/WebRTC path | Safe to omit without `cam` |
| `mario` | Kokoro model/voice files mounted at `MARIO_MODELS_HOST_DIR` (`MARIO_MODEL`, `MARIO_VOICES_PATH`) | Host-voice generation unavailable; stream still plays |
| `tor` | Writable `./data/tor` for hidden-service state | `.onion` audio-only door unavailable; clearnet door unaffected |
| `indiegen` | Valid `INDIEGEN_CONTEXT` build context | Image cannot build; no generated library |

For a minimal playing stream, use the core set from step 4. To run a subset of
optional services, add them explicitly, for example:

```bash
docker compose up -d --build icecast liquidsoap caddy indiegen mediamtx tor
```

Do not publish Icecast or Liquidsoap ports; Caddy remains the only door.
