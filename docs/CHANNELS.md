# Alternative channels for the radio

Research notes on broadcast platforms and transports that could channel this
radio, filtered against the station's spirit. Every claim here was verified
against the project's actual documentation or a real test — see the
*Verification status* column and the *Verified end-to-end* section.

Last updated: 2026-11-10.

## The filter (spirit, restated as criteria)

From `README.md` and `PLAN-LEGAL-AR.md`:

1. **Closed circle, unlisted.** Not in any directory. 404, not 401. Per-person revocation.
2. **Own content.** Generated by indiegenerator (deterministic, offline, no samples, no third-party audio → $0 royalties). Tracks pass gates before entering.
3. **Self-hosted, open source.** `docker compose up`. No SaaS, no CDN (hls.js vendored). No monthly fees.
4. **Privacy-first.** Credentials out of logs, out of the address bar. No third-party tracking.
5. **DIY / artisanal.** Laptop in the Sierras. Hand-installed tracks. Radio never restarts itself.
6. **Anti-corporate.** No algorithms, no ads, no ToS, no listener caps.
7. **Ever growing.** More generators, voices, noises on the same stream. The door does not change; what comes through it does.

A channel is **Aligned** if it keeps all seven. **Partial** if it bends one or two. **Anti** if it breaks the core.

## Verified end-to-end

### Tor v3 hidden service — aligned, with one architectural caveat

- **Tested.** Ran Tor in a container, pointed a hidden service at TinyIce on loopback, fetched the `.onion` HLS playlist over Tor SOCKS → HTTP 200, ~7 s latency. Hidden service address generated and served.
- **Client auth.** Per-client x25519 keys (`.auth` files). Revoke by deleting the file + reload. Fits the closed circle.
- **Secure cookies over `.onion`.** Tor Browser treats `.onion` as a potentially trustworthy origin (Mozilla Bug 1633015, fixed in Firefox 77). `Secure` cookies work, but only if the onion service is on loopback — ours is (Tor daemon on the same box as Caddy).
- **Caveat.** Our canje exchange redirects to the clearnet frontend (`radio.daza.ar` on Cloudflare Pages). A Tor listener following that redirect leaks their IP. So the Tor door as designed is **not anonymity-preserving for the player page**. Mitigations:
  - Tor door = audio-only (VLC/mpv with the token in the URL, no player page), or
  - Serve a minimal player page over the `.onion` too, skipping the redirect.
- **Verdict.** Aligned. Solve the redirect before shipping.

### TinyIce v2.12.3 — aligned, verified behind our actual door

- **Tested.** Ran TinyIce in a container aliased as `icecast` in the same Docker network as Caddy, using our real `Caddyfile` and a generated `tokens.caddy`. Results:
  - No credential → **404** (door closes).
  - With token → **HTTP 200, 47 KB in 3 s** (audio streams through the door).
  - Canje → **302 + Set-Cookie** (exchange works).
- AutoDJ scanned the music dir (1 file, 1 added) and served HLS segments (200).
- **Caveats (real, not blockers):**
  - AutoDJ **re-encodes** audio (lossy for our already-encoded MP3 128 tracks).
  - Gating is username+bcrypt / shared source password — our token+cookie door must still sit in front (Caddy). It does.
  - CVE-2026-45327 (WebRTC ingest auth bypass) — patched in v2.5.0; tested v2.12.3 is patched.
- **Verdict.** Aligned transport. Single Go binary, ~27 MB, Apache 2.0, no Docker required for the binary itself.

### OpenStudio — aligned, integration concern found

- **Verified (docs).** MIT, self-hosted, one process / one port. WebRTC mesh + Icecast source via HTTP PUT (Opus), mix-minus for call-in participants, per-track WAV recording, on-device Whisper transcription, zero tracking, self-hosted fonts (no CDN).
- **Integration concern.** Streams **Opus/WebM** by default (MediaRecorder). Our radio is **MP3**. Feeding our Icecast requires either (a) a separate Opus mount + Liquidsoap decode/re-encode, or (b) a transcoder. Not a blocker, but a real design decision.
- **Role.** Live-show overlay (live mount + Liquidsoap fallback), not a 24/7 base. When a show ends the mount goes silent; Liquidsoap's fallback handles continuity.

### Funkwhale — partial, gating model confirmed

- **Verified (docs).** Private pod is feasible: federation off, allow-listing, anonymous access off, libraries set to Private with per-user grants. Revocation = delete user.
- **Gating friction.** Account-based (username+password), not token-link. Listeners must create accounts. Heavier stack (Django + Postgres + Redis).
- **Federation-off.** Docs say "Whether to enable federation features" — off means off. Not packet-captured, but the toggle is explicit.
- **Role.** Catalog companion for on-demand listening of the indiegenerator library.

### Meshtastic — text-only side channel (verified)

- Codec2 voice only works on **2.4 GHz radios (LORA_24)**, PTT-style, store-and-forward. A 3 s clip took 11 min in a 2026 study. Sub-1 GHz bands cannot carry continuous audio.
- **Not a music transport.** Alerts only.

### FM in Argentina — illegal unlicensed (verified)

- No US-style Part 15 exemption. ENACOM licenses FM via concursos públicos.
- `PLAN-LEGAL-AR.md` already covers this: internet-only radio needs **no ENACOM license** and, with own/CC content, **$0 in royalties**. Adding FM = license + SADAIC/CAPIF fees (~$28k–$45k + alícuotas).
- **Stays a separate legal project, not a bolt-on.**

### Owncast — not recommended (verified)

- Audio-only is **not supported** (issue #3704, closed `not_planned`; maintainer recommends Icecast for audio).
- Gating is a **shared password + admin-flipped `revoked` flag** that kicks everyone — breaks per-person revocation.
- Federation and directory listing can be disabled. Good reference for the unlisted-`/watch/<token>` page pattern, wrong transport for us.

## What did not align (avoid)

- **SaaS streaming hosts** (Caster.fm, Radio.co, Live365, Zeno, RadioKing) — fees, caps, directories, tracking.
- **Mainstream platforms** (Twitch, YouTube, Spotify, SoundCloud) — algorithms, ads, ToS, no privacy.
- **AI DJ services** (SUB/WAVE) — third-party generated content; breaks the "ours, no royalties" promise unless repositioned as our generator output.
- **CDN-dependent delivery** — contradicts "no CDN, vendor locally."
- **Public fediverse announce** — is a directory.
- **Shortwave pirate / unlicensed FM** — illegal in AR and public by nature.

## Expansion framing

The README says: *"Other generators, other music, other voices, other noises, other sounds — built in weird ways — will land on this same stream soon. The door does not change; what comes through it does."*

The most aligned options **feed the existing stream** without changing the door:

1. **lumbung timesharing** — other nodes' streams land on ours via Liquidsoap `input.http`. Most expansion-aligned. Cheapest.
2. **OpenStudio** — other voices land on ours via Icecast source. Second most aligned.

Catalog companions (Navidrome/Funkwhale) are **parallel surfaces**, not expansion of the stream.

## Remaining (honestly unverified) gaps

1. **TinyIce under load** — no stress test. Docs claim 10k listeners / 250 MB, not measured by me.
2. **OpenStudio → Icecast live-override Liquidsoap config** — the `input.http` fallback pattern is standard, but not tested with OpenStudio specifically.
3. **Funkwhale federation-off packet capture** — docs say off = off, but not verified on the wire.

## Legal note (AR)

`PLAN-LEGAL-AR.md`: internet-only radio needs **no ENACOM license** and, with own/CC content, **$0 in royalties**. The moment we add FM/AM, that changes: spectrum licensing via ENACOM + SADAIC/CAPIF fees. Physical FM is a **separate legal decision**, not a free upgrade. Tor/I2P/P2P/internet transports do not change the legal posture.

## Principles to keep for any new channel

- **The door does not change; what comes through it does.** A new channel must not become a second, looser door.
- **No public announce.** If a platform's default is "discoverable," turn it off or skip it.
- **Credentials stay out of logs and URLs.** Applies to every new transport.
- **Own content only.** No third-party audio sneaks in via "channels."
- **Gating is the hard part for P2P/decentralized.** If we cannot gate it per-person, it is not a channel for this radio.
